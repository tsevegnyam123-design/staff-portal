# Staff Portal — Wi-Fi IP-д суурилсан ирц + Google Sheets синк

## 2026-11-28: Нарны Титэм салбарын Wi-Fi (IP) хязгаарлалт

- Зөвшөөрөгдсөн **нийтийн IPv4: `112.72.7.161`**.
- Ажилтнууд порталаар **нэвтрэх, ээлж/цалин/кассын зөрүү харах** эрхтэй хэвээр.
  Зөвхөн **Ирсэн/Явсан** товч нь тухайн салбарын нийтийн IP-д холбогдсон
  үед ажиллана. Мобайл дата, VPN, бусад Wi-Fi-аас ирц дарж болохгүй.
- Өмнөх GPS geofence-ийн оронд Wi-Fi IP хязгаарлалт ажиллана:
  **GPS-ийн зөвшөөрөл шаардахгүй.**
- Browser Wi-Fi сүлжээний нэр (SSID)-ийг уншиж чаддаггүй. Сервер Supabase
  gateway-ийн `cf-connecting-ip` толгойг ашиглах ба `X-Forwarded-For`,
  `X-Real-IP`, браузерийн JSON, URL дахь IP-д итгэхгүй. Толгой дутуу,
  тодорхойгүй, IPv6 эсвэл өөр IP ирвэл **автоматаар зөвшөөрөхгүй**.
  Gateway-ийн IP мэдээллийг бодит салбарын холболтоос турших шаардлагатай.
- Дэлгэцэнд тухайн сүлжээ зөвшөөрөгдсөн эсэхийг харуулна. Сервер POST
  хүсэлт бүрт дахин IP шалгадаг; хуурамч UI дээр даралт зөвшөөрөхгүй.
- Интернетийн үйлчилгээ үзүүлэгч IP-г солих, VPN, прокси/Cloudflare Worker,
  нэг нийтийн IP-г хэд хэдэн салбар хуваалцах зэрэг нь найдвартай байдалд
  нөлөөлж болно. Нийтийн IP таарах нь тухайн хүн салбарт биеэрээ
  байгааг **бүрэн батлахгүй**.
- IP өөрчлөгдвөл зөвхөн эрх бүхий админ Supabase SQL Editor-оор
  `portal_v2_attendance_allowed_ips` хүснэгт дэх тухайн салбарын
  хаягийг шинэчилнэ. Бусад салбарын IP-г автоматаар зөвшөөрөхгүй.
- Энэ өөрчлөлт `database/portal_v2_attendance_wifi.sql` migration-д бий.

> Доорх GPS байршлын хуучин заавар нь өмнөх хувилбарын тайлбар болохоос
> одоо мөрдөж буй Wi-Fi IP хувилбарын хэрэглэгчийн заавар биш.


## Ашиглаж буй систем

- Портал: https://tsevegnyam123-design.github.io/staff-portal/
- Supabase: `portal_v2_attendance`, `portal_v2_attendance_sites`
- Google Sheets: https://docs.google.com/spreadsheets/d/1Q_fKf_MUcmmgKVvOyTZx9R5cDi3xy4kiA1tJNaHfoJI/edit
- Google Apps Script код: `google-apps-script/AttendanceSync.gs`.

**Хувийн байршлын хөдөлгөөний түүх хадгалахгүй.** Ирц дарах үед
браузер GPS-ээ зөвшөөрснөөр сервер зөвшөөрсөн салбарын төв болон
радиустай харьцуулна. Ажилтны GPS координат ирцийн хүснэгт болон
Google Sheets-д хадгалагдахгүй; зөвхөн байрлалын хэмжилтийн
нарийвчлалыг хадгална. Браузер байршлаа илгээж чаддаг төхөөрөмжөөс
ашиглах шаардлагатай; хуурамч GPS-ийг бүрэн илрүүлэх баталгаа биш.

## Менежер: салбарын байршил тохируулах

1. Салбар дотор, GPS боломжтой утаснаас менежерийн эрхээр нэвтрэх.
2. **Ирцийн байршил** табыг нээх.
3. Радиусыг 50–500 м дотор тохируулах (эхний утга **150 м**).
4. **Энэ байршлыг төв болгох** товч дарж байршлын зөвшөөрөл олгох.
5. Менежер байршилд үнэхээр байгаа эсэхээ шалга. Тохируулга хийгдээгүй бол ажилтан
   **Ирсэн/Явсан** товч дарах боломжгүй.

Менежер байршлыг дахин тохируулах эрхтэй. GPS хэмжилтийн алдаа
100 м-ээс их байвал хүсэлт буцаана. Ажилтны тасралтгүй байршлыг
систем хянадаггүй.

## Ажилтан: Ирсэн / Явсан

Ажилтны хуудасны **Ирц бүртгэх** товч:

- **Ирсэн** — тухайн мөчийн серверийн цагаар ирцийг нээнэ.
- **Явсан** — нээлттэй ирцийг тухайн мөчийн серверийн цагаар хаана.
- Давхар **Ирсэн** / нээлтгүй **Явсан** дарахыг мэдээллийн сан хориглоно.
- Нэг өдөрт хэд хэдэн орж/гарсан бүртгэл байж болно (нэгэн зэрэг нэг нээлттэй бүртгэл).
- **Явсан дараагүй**: ирсэн өдрийн дараагийн **01:00** цагаар
  буруу/дутуу хаалт хийж, `auto_missing_out` төлөвтэй болгоно.
  SQL scheduler 5 минут тутамд шалгана, огноо нь **01:00** байна.
  Үүнийг **бодит ажилласан 9 цаг** гэж тооцохгүй, `Нийт ажилласан цаг` = `-`.
  Менежер дараа нь бодит баримтаар засварлах тусгай workflow шаардлагатай.

**Анхаарах ноцтой хязгаарлалт:** Одоогийн ээлжийн хуваарьт
**23:45–08:45 шөнийн ээлж** бий. 01:00-д автоматаар хаах хэрэглэгчийн
хүсэлт нь шөнийн ээлжийг 01:00-ээс хойш ажиллах боломжгүй болгож, “Явсан дараагүй”
гэж тэмдэглэх тул ночной ээлжийн тусгай тасалбарын дүрмийг менежер
шийдэж батлах хүртэл энэ системийг **бодит шөнийн цагийн цалин бодоход
шууд ашиглахгүй**. Хүсэлтийн дагуу 01:00 дүрмийг бүх бүртгэлд мөрдөнө.

## Google Sheets-ийн бүтэц

- **Номинзул**: эхний хэрэглэгчийн одоо байгаа жишээ бүртгэлийг хадгалсан.
- Бусад ажилтан бүр тусдаа, өөрийн нэртэй хуудастай.
- Ажилтны sheet: **A–G** `Өдөр / Ирсэн цаг / Явсан цаг / Нийт ажилласан цаг / Тайлбар / Өдрийн цаг / Шөнийн цаг`.
- **Өдрийн цаг**: тухайн бүртгэлд 06:00–22:00 хооронд бодитоор ажилласан минут.
- **Шөнийн цаг**: тухайн бүртгэлд **22:00–дараагийн 06:00** хооронд
  бодитоор ажилласан минут; шөнө дунд дамнасан бүртгэлийг хоёр огноонд зөв хуваана.
- `Нийт ажилласан цаг = Өдрийн цаг + Шөнийн цаг`. **Зөвхөн `Хэвийн`
  (бодит Явсан дарсан) ирц** цагт орно; `Явсан дараагүй`, `Яваагүй`
  төлөвт өдрийн/шөнийн цаг хоёулаа `-` гэж гарна.
- **Далд H багана** `Portal record ID` нь автоматаар бүртгэсэн мөрийг
  дахин давхардахгүйгээр шинэчлэхэд хэрэгтэй.
- **Info**: цалингийн `өмнөх 26 — одоогийн 25` хугацаагаар
  ажилтны код, нэр, салбар, хэвийн ирцийн хоног, баталгаатай ажилласан
  цаг, явсан дараагүй, нээлттэй ирцийг нэгтгэнэ.
  **K: Өдрийн цаг, L: Шөнийн цаг** нь мөн адил мөчлөгийн дүн;
  **H-ийн нийт цаг = K-ийн өдрийн цаг + L-ийн шөнийн цаг**.
  Нэг өдөрт хоёр удаа орж гарсан бол цагийг нийлүүлнэ, харин
  хэвийн ирцийн хоногийг 1 өдөр гэж тоолно.
- Явсан дараагүй бүртгэлийг **ажилласан цагт нэмэхгүй**.
- Анх хэрэглэгчийн гараар оруулсан мөрүүд автоматаар өгөгдлийн сан руу
  импорт хийгдээгүй; тэр мөрүүд хэвээр үлдэнэ. Порталаас шинээр орсон
  мөрүүдийг **H баганын `Portal record ID`**-аар ялгана.
  Өмнө F-д байсан ID-уудыг H-д шилжүүлэх хамгаалалт скриптэд бий.
- Хуучин `Номинзул` жишээний 2026/11/20 ба 2026/11/21 мөрөнд F/G
  томьёо нэмсэн. **Гараар оруулсан бусад түүхэн мөрүүд Info-д автоматаар
  орохгүй**: Info нь зөвхөн порталын сервер дээр бүртгэлтэй бодит ирцээс
  тооцно.

## Ирсэн болон Явсан үед ашигласан төхөөрөмжийн мэдээлэл (2026-11-28)

- **Ирсэн** товч дарахад браузерээс мэдэгддэг **ерөнхий төхөөрөмж / үйлдлийн
  систем / браузерийн нэр** серверийн `check_in_device` баганад хадгалагдана.
- **Явсан** товч дарахад **тухайн үеийн** мэдээлэл тусдаа
  `check_out_device` баганад хадгалагдана. Ирсэн, Явсан хоёр өөр
  төхөөрөмжөөс дарагдсан байж болно.
- Браузер утасны өөрийн нэр (жишээ: “Номинзулын iPhone”), серийн дугаар,
  IMEI, MAC хаягийг уншиж чадахгүй. Тиймээс ерөнхий `iPhone · iOS · Safari`,
  `Android · Chrome` зэрэг **ойролцоо тайлбар** гарна.
- Эдгээр утга нь техникийн аргаар өөрчлөгдөж болдог учир төхөөрөмжийн
  эзэн, ажилтны хэн болохыг **баталдаггүй**.
- **Google Sheets ажилтан тус бүрийн tab:**
  **I = Ирсэн төхөөрөмж**, **J = Явсан төхөөрөмж**.
  **H = далд Portal record ID** хэвээр.
- Хуучин бүртгэлүүдийн төхөөрөмжийн мэдээлэл өмнө нь хадгалагдаагүй
  тул буцааж нөхөх боломжгүй, `—` гэж гарна. `Явсан дараагүй`
  автоматаар хаагдсан ирцийн `Явсан төхөөрөмж` мөн `—`.
- Бүтэн User-Agent, төхөөрөмжийн fingerprint, байнгын төхөөрөмжийн ID-г
  хадгалахгүй. Ажилтнуудад энэ мэдээллийг ирцийн хяналтад ашиглах тухай
  мэдэгдэж, Google Sheet-ийн хандалтыг зөвхөн эрх бүхий хүмүүст олго.
- **Apps Script-ийн өмнөх код автоматаар шинэчлэгдэхгүй.** GitHub дахь
  `google-apps-script/AttendanceSync.gs`-ийн хамгийн сүүлийн хувилбарыг
  Apps Script `Code.gs`-д бүхэлд нь сольж **Save** дар. Байгаа
  `ATTENDANCE_SYNC_TOKEN` property болон 5 минутын trigger-ийг солих
  шаардлагагүй. `synchronizeAttendance`-ийг нэг удаа Run хийж,
  **Executions** дээр амжилттай болсныг шалга.

## **Google Sheets автомат синкийг идэвхжүүлэх (заавал)**

⚠️ **Одоогоор код болон хуудсууд бэлэн, харин синк өөрөө зөвшөөрөлгүй
автоматаар ажиллахгүй.** Үүнийг нэг удаа тохируулах хэрэгтэй.

1. Нууц **32 буюу түүнээс олон тэмдэгттэй random token**-ийг өөрийн
   нууц орчинд үүсгэ. Чат/репозиторид бүү оруул.
2. <https://supabase.com/dashboard/project/zxhbufwncnijmpwzokvt/functions> →
   **Edge Functions → Secrets** дээр `GOOGLE_SHEETS_SYNC_TOKEN`
   нэртэй secret-ийг тэр token-оор үүсгэ.
3. Дээрх Google Sheets-ийг нээгээд **Extensions → Apps Script** сонго.
4. `google-apps-script/AttendanceSync.gs` файлын **хамгийн сүүлийн
   хувилбарын бүтэн кодыг** Apps Script editor-т хуулж хадгал.
   Өмнө нь синк суулгасан бол **хуучин кодыг заавал солих**
   шаардлагатай: өмнөх код F-д ID бичдэг байсан бол шинэ код F/G-д
   өдрийн/шөнийн цаг, H-д ID бичнэ.
5. Apps Script **Project Settings → Script Properties** дээр
   `ATTENDANCE_SYNC_TOKEN` нэртэй property-д **яг ижил token** оруул.
6. Editor-оос `installAttendanceSync` функцийг сонгон **Run**
   хийгээд Google-ийн шаардсан албан ёсны зөвшөөрлийг зөвшөөр.
   Ингэснээр `synchronizeAttendance` 5 минут тутамд ажиллах
   **time-driven trigger** үүсгэнэ.
7. **Executions** таб дээр алдааг шалгаж, Google Sheet-ийн
   `Info` болон нэг ажилтны tab-д өөрчлөлт орж буйг баталгаажуул.

Token нь зөвхөн серверийн ирцийн экспортод зориулагдсан.
Ажилтны PIN, цалин, GPS координат, нэвтрэх сешн экспортод орохгүй.

Хэрэв 403 гарвал token хоёр талд ижил эсэхийг шалга.
Хэрэв 503 гарвал Supabase secret тохироогүй.
Google Sheet хувийн өгөгдөл агуулдаг тул **public share** болгож болохгүй.

## Тестлэх

- Байршил тохируулаагүй үед `Ирсэн` идэвхгүй.
- Зөвшөөрөгдсөн салбар дотор `Ирсэн` амжилттай;
  давхар `Ирсэн` буцаагдана.
- Гаднаас ирсэн/явсан дарахад сервер 403 буцаана.
- `Явсан` дарахад серверийн цагт `completed` төлөвтэй.
- 01:00-ээс өнгөрсөн нээлттэй ирц `auto_missing_out`; ажилласан цаг `-`.
- Синк дараалан хоёр ажиллахад Google Sheet-ийн мөр **давхардахгүй**.
- Шинэ ажилтны sheet автоматаар үүснэ.
- `Info`-д 26–25 мөчлөгөөр нэгтгэл гарна.
